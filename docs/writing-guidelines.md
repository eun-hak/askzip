# askzip 안내글 작성 가이드라인 (자동 발행 루틴용)

자동 루틴·수동 작성 공통. **사실 정책 위반 글은 발행하지 않는 것이 발행하는 것보다 낫다.**

## 사실 정책 (위반 시 발행 중단)
- **1인칭 경험 문장 절대 금지**: "운영자가 해보니", "직접 해보니", "필자", "제가" 류 전부. 경험담은 실제 운영자 경험이 있을 때만 사람이 넣는다.
- 수치·기한·수수료·제도명은 **웹 검색으로 공식 출처(정부·공단·법령) 확인 후에만** 기재. 확인 안 되면 수치 없이 서술하고 "기관 확인 필요"로 정직하게 안내.
- 최상급·과장 표현 금지. 확인 안 된 제도 변경 단정 금지.
- publishedAt = updatedAt = **실제 발행일(KST)**. 소급·미래 날짜 금지.

## 구성 요건
- 본문 글자수(문자열 합계) **2,400~3,400자** — 매일 같은 두께가 되지 않게 범위 안에서 다르게
- h2 5개 이상(마지막은 FAQ), table 2개 이상, steps 0~1개
- tip·notice 각 1개 이상, **글별 고유 warning 1개** (다른 글과 동일 문구 금지)
- FAQ 5개 이상, 그중 "~가 안 돼요" 실패·막힘 케이스 2개 이상
- toc는 h2 id와 일치, relatedSlugs는 실제 존재하는 slug 2~3개
- 절차 나열이 아니라 **판단 기준·상황 분기** 중심으로

## 파일 형식
- `src/data/types.ts`의 `Article` 타입, 기존 글(`src/data/articles/*.ts`) 컨벤션과 동일하게
- content 블록: paragraph/h2/steps/faq/table/warning/tip/notice만 (image는 사람이 캡처 확보 시에만)
- 문자열은 작은따옴표, 본문 내 따옴표는 큰따옴표 문장부호(" ")로
- readingTime = 글자수 ÷ 500 (분, 반올림)
- 파일 하단에 `TODO(스크린샷)` 슬롯 주석 2~3건

## 등록 절차 (신규 글 1편마다)
1. `src/data/articles/<slug>.ts` 생성
2. `src/data/articles/index.ts`에 import + articles 배열 등록 (해당 카테고리 구역에)
3. `src/data/sources.ts`에 공식 출처 2~3개 등록 (label에 도메인 병기, 정부·공공 도메인 위주)
4. `docs/content-queue.md`의 해당 항목을 `[x]`로 바꾸고 발행일 기입

## 발행 전 자동 검수 (전부 통과해야 push)
```bash
# 1인칭 스캔 — 실제 위반만 0건이어야 함 ("문제가" 같은 오탐은 제외하고 판단)
grep -n "운영자\|필자\|직접 해보" src/data/articles/<slug>.ts
# 빌드
npm install && npm run build
```
검수 실패를 고치지 못하면 **커밋·푸시하지 말고 종료**한다.

## 문체
존댓말 안내체, 문단 2~4문장, AI 상투어("다양한", "간편하게" 남발) 금지. 독자가 "왜/언제/무엇을 골라야 하는지"를 얻어가는 글.
